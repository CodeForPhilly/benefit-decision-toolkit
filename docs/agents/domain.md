# Domain docs

## Layout and reading rules

Use one root `GLOSSARY.md` and `docs/adr/` for repository-wide decisions.
Before exploring, read the glossary and ADRs relevant to the work.

If these files are absent, proceed silently. The domain-modeling skill
creates them as terms and decisions are resolved.

## Vocabulary

Use the glossary's terms in issues, proposals, hypotheses, and tests.
If a concept is missing, reconsider the terminology or note the gap
for domain-modeling.

## Decisions

Surface conflicts with existing ADRs explicitly, identifying the ADR
and explaining why the decision may need reconsideration.
